Manual da versão web

Portal de Estudos

Sem Python, sem BAT: abre como um site normal.
← Voltar ao portal
Onde os dados ficam?
Progresso dos checklists, favoritos e último acesso usam LocalStorage. Materiais, memória de estudo, links, tarefas, sessões, Pomodoros e histórico do assistente usam IndexedDB. Esses dados pertencem ao navegador e ao domínio em que o site estiver publicado.

1. Como usar

Abra o endereço do site no Chrome, Edge, Firefox ou Safari. Não é preciso extrair ZIP nem iniciar um servidor Python. Após o primeiro carregamento, o Service Worker mantém os arquivos principais disponíveis offline em navegadores compatíveis.

Guias e checkboxes

Abra uma disciplina, marque os itens normalmente e use “Revisar”, “Dominado” e “Nota” por seção. O portal também grava o último ponto de leitura.

Busca

A barra superior pesquisa os seis guias, materiais adicionados e links salvos usando BM25 e fusão de rankings no próprio navegador.

Materiais

PDF, DOCX, PPTX, XLSX, EPUB, HTML, Markdown, TXT, CSV, JSON, RTF, VTT e SRT podem ser guardados e indexados. PDFs usam PDF.js carregado sob demanda.

Foco e metas

Pomodoro, sequência, tarefas, metas semanais e estatísticas ficam gravados neste navegador.

Links

Salve referências com tags, disciplina, descrição e fixação. Importe favoritos em HTML, Markdown ou JSON e exporte nos mesmos formatos.

Perguntar aos materiais

O modo web recupera evidências e trechos relevantes com fontes. Ele não envia seus documentos para uma IA externa.

2. Materiais e privacidade

Os arquivos adicionados pela Biblioteca são armazenados no IndexedDB local do navegador. DOCX, PPTX, XLSX e EPUB são extraídos no navegador. Para PDFs, o portal carrega a biblioteca PDF.js por HTTPS quando necessário e processa o arquivo localmente.

Importante: limpar “dados do site” no navegador pode apagar os dados locais. Faça backups periódicos pelo botão Exportar backup.

3. Backup e troca de computador

Use Exportar backup para gerar um JSON contendo progresso, memória, links, tarefas, Pomodoros, histórico e materiais web. No outro navegador, abra o portal e escolha Restaurar backup. É a forma recomendada de migrar entre computadores ou navegadores.

4. YouTube

Transcrições manuais continuam funcionando: cole o link, título, idioma e texto da aula. Também é possível importar arquivos VTT/SRT na Biblioteca. A captura automática de legendas não funciona numa hospedagem puramente estática porque o YouTube impede essa consulta direta a partir do navegador; ela exigiria um backend.

5. Importar uma página por URL

O botão de URL tenta ler a página diretamente. Alguns sites permitem isso e outros bloqueiam por CORS. Se houver bloqueio, baixe a página ou arquivo e use Adicionar materiais.

6. Assistente

Na versão web, “Perguntar aos materiais” usa recuperação local e apresenta trechos relevantes com indicação das fontes. O Ollama não é chamado pelo GitHub Pages. Isso evita depender de um servidor no seu computador, mas não produz a mesma síntese generativa da edição local com backend.

7. Publicação no GitHub Pages

O pacote já contém .github/workflows/pages.yml e .nojekyll. Coloque os arquivos na raiz de um repositório, envie para a branch main e habilite GitHub Pages usando GitHub Actions. O workflow publica o site automaticamente.

8. O que continua funcionando como site

Guias, 1.679 checkboxes, progresso, favoritos, recentes, retomada, Revisar/Dominado/Notas, sessões, Pomodoro, metas, tarefas, links, importação/exportação de links, biblioteca de materiais, pesquisa híbrida, perguntas por evidência, backup/restauração, diagnóstico e funcionamento offline.

Duas diferenças inevitáveis da versão puramente estática: captura automática de legendas do YouTube e geração via Ollama precisam de backend. Todo o restante foi adaptado para o navegador.
